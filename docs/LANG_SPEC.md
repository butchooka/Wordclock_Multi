# Adding a language (LANG_SPEC v1.0)

A language consists of exactly three files plus two list entries. Nothing else is changed.

| File | Content |
|---|---|
| `arduino/Wordclock/src/wc_lang_XX.h` | grid, word positions, time grammar `time_words()`, `INFO_DE`/`INFO_EN` block, web texts `UI_JSON`, defaults (host = word for wordclock in lower case, hotspot = same in CamelCase, capital, POSIX time zone, date format) |
| `esphome/wordclock_multi/lang/lang_XX.yaml` | device name, hotspot, capital, entity names, colour and effect names |
| `models/lang/lang_XX.scad` | the same grid for the 3D models (+ optional font for other scripts, optional filler default) |
| `models/lang/lang_all.scad` | `include <lang_XX.scad>` and entry in `LANGS` |
| `models/Wordclock_Model.scad` | option `XX:Name` in the `LANG` line |

Start from the files of DE or GB (GB is the reference for all keys). `XX` = ISO country code of the main country.
Languages of countries: DE, GB, CN, CZ, DK, ES, FR, GR, HU, ID, IT, JP, KR, NL, NO, PL, PT, RO, SE, TR, TZ = Swahili, UA.
Dialects: `dialect_` + short code: `dialect_BAD` = Baden dialect, `dialect_CH` = Swiss German (CH = country code),
`dialect_SWG` = Swabian (ISO 639-3). Other languages: EO = Esperanto (language code, no country), VA = Latin, fictional
languages and script variants `scifi_...`. All lists (docs/languages/, config.h, wordclock_multi.yaml, README) use this
order: countries (DE and GB first), dialects, other languages. `tools/make_info.py` groups by the prefix
(`dialect_` / `scifi_`); a new constructed or classical language without prefix is added to `OTHER` there.
Fictional languages (from films, books, series): `scifi_` + short code, e.g. `scifi_TLH` (tlhIngan Hol), `scifi_QYA` (Quenya),
`scifi_HVA` (Valyrio), `scifi_NAV` (Na'vi). They sort after the real languages in all selection lists. Code, own name,
device name and texts use the name of the language itself, never the name of a film, series or franchise.
The code is the same everywhere (file names `wc_lang_scifi_TLH.h`, `lang_scifi_TLH.yaml`, `lang_scifi_TLH.scad`,
`LANG_scifi_TLH` in the .scad, `LANG = "scifi_TLH"`, `docs/languages/LANG_scifi_TLH.txt`). C++ names must not contain a double
underscore (reserved): namespace e.g. `wc_scifi_tlh`, `wc_dialect_bad`. The same scheme applies to dialects
(`wc_lang_dialect_BAD.h`, `LANG = "dialect_BAD"`, ...).

## Script variants (front only)

A script variant prints the front of an existing language in another script (e.g. runes) and needs no firmware:
the clock runs the base language, only the 3D model gets its own entry. It consists of
`models/lang/lang_scifi_<NAME>_<BASE>.scad` (generated by `tools/make_variants.py` from the grid of the base and a
letter table; field 7 of the entry = base language), the include line and `LANGS` entry in `lang_all.scad` and the
option in the `LANG` line of `Wordclock_Model.scad`. `check_lang.py` checks it against the base (same layout,
every letter always replaced by the same character); `make_info.py` lists it (docs/languages/LANG_scifi_..txt, overview,
README, SETUP tables); `render_fronts.py` renders it with the lit cells of the base.
Only fonts that come with the operating system or OpenSCAD (nobody has to download anything); add the font file
to `LANG_FONTS` in the FreeCAD macro and in `render_fronts.py`. Available: `scifi_RUNE_GB`, `scifi_RUNE_DE` (Anglo-Saxon
runes, Segoe UI Historic of Windows 10/11). Not possible without a download: pIqaD, Aurebesh, Hylian (no font in
Windows/macOS/Linux, pIqaD and Aurebesh are not even in Unicode).
After a change of the base grid run `python3 tools/make_variants.py` again.

## Grid rules (16 x 16, row 1 = top)

- Column 1 and 16 of rows 1-13: `*` (temperature dots, left outside, right inside).
- Rows 1-13, columns 2-15: time words.
- Fillers: every cell that is never lit is a lower case `x` (in all rows, also rows 14-16). `check_lang.py` checks
  this against the time grammar (never lit = `x`, `x` = never lit). The models print fillers as `FILLER`
  (`auto` = default of the language, or `X`, `dot`, `-`, `+`, any character), the web interface and the time text
  never show them. Optional field 6 of the entry in `lang_XX.scad` is the default of the language for
  `FILLER = "auto"` (e.g. `"dot"` for scripts where an X looks foreign: CN, JP, KR); without it `X` is used:
  `LANG_XX = ["XX", "Name", [16 rows], "OpenSCAD font", "FreeCAD font file", "dot"];`
  Upper case `X` is a normal letter (e.g. GB SIX, FR DIX). Extra words (easter egg) are words, not fillers.
- Row 14: minute row: `+`, digits `1234`, the word MINUTE(S) in the language (plural/singular as the language needs).
- Row 15: VENT and ALARM words in the language. Row 16: BATTERY word, then 10 bars `|` (usually columns 7-16).
- Exactly 16 characters (code points) per row. One character = one LED. Special letters (Ä, Ø, Ж, 한, 時) are one cell.
- Lower case letters are allowed for scripts that need mixed case (e.g. tlhIngan Hol: q and Q are different
  letters). The lower case `x` stays the filler in every language, a language with a letter x writes it as `X`.
  Lower case descenders (g j p q y) are reduced and pushed up like Ç (not cut), so they stay readable.
- Characters must print well at 7 mm cap height in a 8.4 mm cell (no stacked accents, no connected scripts).
- The OpenSCAD model places a character exactly only if it has metrics in `METRICS_LIBERATION_BOLD` /
  `METRICS_DEJAVU_BOLD` of `Wordclock_Model.scad` (A-Z, 0-9, + - ', the Latin-1 capitals with accents, from
  Latin Extended-A/B: Ą Ć Ę Ł Ń Ś Ź Ż, Ğ İ Ş, Ă Ș Ț, Č Ď Ě Ň Ř Š Ť Ů Ž, Ő Ű, Ĉ Ĝ Ĥ Ĵ Ŝ Ŭ, Ā Ē Ī Ō Ū Ȳ;
  Greek capitals Α-Ω, Cyrillic capitals А-Я Ё Є І Ї Ґ and the lower case letters a-z);
  other characters are only roughly centred. A new special character needs a core change (metrics from the TTF files).
  FreeCAD measures the glyphs itself and checks every language against the character map of the font
  (`FONT_AUTO`): if the chosen font lacks a character (e.g. Ȳ in some Arial versions, kana/kanji, Hangul), it takes
  the own font of the language (field 5), then `LANG_FONTS` / `FONT_FALLBACKS`, then any installed font that
  contains all characters; without one the language is skipped (never cut as empty boxes). A new language with
  its own script: add its preferred font files to `LANG_FONTS` in the macro (and to `LANG_FONTS` in
  `tools/render_fronts.py` for the preview images).
- All letters stand on one baseline. Capitals with accents (È, Ü, Ã ...) are reduced around the baseline to fit into
  the chamber (approx. 6 mm instead of 7 mm). A too long descender is cut at the chamber edge for Q and J
  (`TAIL_CUT`), other characters with a long descender (Ç) are reduced and pushed up.
- Extra words (easter egg): every language gets a greeting or a typical saying from free cells (e.g. GB HELLO,
  TZ HAKUNA MATATA) as `WcWord` list in `WC_LANG.extra`. The switch is named after the phrase in the language
  (`swExtra` in `UI_JSON` and `t_sw_extra` in the YAML, pattern like the VENT switch, e.g. "Show HELLO",
  "HALLO anzeigen"), off by default; `extra_hidden: "false"` in the YAML.
  As long as the time is unknown (start, no connection) the clock shows the extra words instead of the prefix,
  whatever the switch says (pulsing blue while the hotspot is open). So the extra must look good on its own.

## Time grammar

`time_words(valid, hour, minute, show_minutes, m)` marks words with `m.word({row, col, len})` / `m.at(row, col)`
(row/col from 0). `valid == false`: only the prefix (e.g. ES IST) or nothing; this is only used for the text, the grid shows the extra words instead. The text in the web interface is taken from the
grid automatically in the order of the calls, separated by spaces; `m.glue(...)` marks a word like `m.word(...)`
but appends its text without a space (a word split in the grid, e.g. IT "MINUTIO": MINUT + O = MINUTO).
Everything is possible in code: next hour from a certain minute, singular/plural, different hour words,
minute row with the correct plural, etc.

## Info block (time grammar for the documentation)

The header comment of `wc_lang_XX.h` contains the grammar in German and English between the markers
(two spaces indentation, keep the markers):

```
  INFO_DE (tools/make_info.py writes the lines between the markers to docs/languages/LANG_XX.txt)
  Satzbau: ...                       sentence pattern, from which minute the next hour counts,
  :00 ..., :05 ..., ... :55 ...      all 5-minute steps, special cases (1 o'clock, noon/midnight,
  Minutenzeile: + 1 ... / + 2..4 ... singular/plural), minute row singular/plural
  INFO_EN
  Sentence: ...
  INFO_END
```

`tools/make_info.py` builds `docs/languages/LANG_XX.txt` from it (plus grid, all 5-minute steps, special times and four example
grids from `preview.cpp`) and updates `docs/languages/LANGUAGES.txt` and the setup guides (`arduino/README*.md`, `esphome/README*.md`, `docs/setup/SETUP_*_EN/DE.md`)
(all languages are listed there automatically). Never edit the generated files in `docs/languages/`, `docs/setup/` and the setup READMEs by hand.

## Texts

- `UI_JSON`: same keys as GB, values translated; `{ap}`, `{fx}`, `{ssid}`, `{ip}` stay as placeholders.
  Text ticker: `txt` (name), `txt_ph` (placeholder of the input), `txt_start` (button), `txt_started` (message),
  `hint_txt` (hint below the input).
  Do not use `)JSON"` in a text. `html_lang` = ISO language code, `dec` = decimal separator.
- YAML: same substitution keys as GB. Options in palette order (c_0 warm white ... c_7 violet).
  Text ticker: `t_text` (text entity) and `t_text_start` (button), the same words as `txt` / `txt_start`.
- Effect names: one key per effect of `WC_FX` (`fx_<key>` in UI_JSON and YAML).
- Text ticker font: `src/wc_font16.h` covers Latin (incl. Extended-A, Ș Ț), Greek and Cyrillic. A language with
  other letters adds their Unicode range to `charset()` in `tools/make_font.py` and runs it again
  (CJK and Hangul are too large for the flash and are skipped by the ticker).

## Location

The capital of the language must be in the location list `LOC` in `webpage.html` (own spelling, country code,
coordinates, time zone key) with exactly the coordinates and POSIX time zone of `WC_LANG`; otherwise the web
interface shows "custom location". A new time zone also needs an entry in `TZ` and an option in the time zone list.
Languages without a country (Esperanto, fictional languages): take an existing location of `LOC` in a suitable time
zone, no new entries in `LOC`/`TZ`.

## Check

Windows: double-click `tools/check_languages.bat` (checks all languages without changing files and
writes `tools/logs/check_log.txt`, then updates `docs/languages/` and the setup guides with tools/make_info.py; an outdated ESPHome copy is reported,
then run tools/sync_src.py). The filler check and the files `docs/languages/LANG_XX.txt` need g++ (Windows:
`winget install BrechtSanders.WinLibs.POSIX.UCRT`, new window, `g++ --version`). Command line:

```
python3 tools/sync_src.py                                                       # copy .h to ESPHome
python3 tools/check_lang.py XX --words
python3 tools/make_info.py                                                       # writes docs/languages + setup guides (needs g++)
g++ -std=c++11 -Wall -DLANG=XX tools/preview.cpp -o preview && ./preview        # all times
./preview grid 13:47                                                             # lit grid of one time
```
